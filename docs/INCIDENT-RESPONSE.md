# OPS Blueprint V1 — Production Incident Response Protocol

> **제정일**: 2026-09-10  
> **목적**: 프로덕션 장애 발생 시 신속한 감지, 등급 분류, 롤백 및 원인 규명 표준 절차 확립  

---

## 1. 장애 등급 분류 체계 (Severity Levels)

| 등급 | 정의 | 장애 예시 | 대응 목표 시간 | 조치 권한 |
| :---: | :--- | :--- | :---: | :--- |
| **P0 (Critical)** | 서비스 전면 중단, 데이터 유실, 인증 실패, 보안 침해 | • Vercel 500 에러로 사이트 접근 불가<br/>• 워크플로우 저장 후 데이터 삭제<br/>• 타 사용자 워크플로우 열람(RLS 우회) | **즉시 (15분 이내)** | 즉시 롤백 및 개발 완전 중단, 긴급 보고 |
| **P1 (High)** | 핵심 기능 마비, 다수 사용자 영향 | • 에디터 캔버스 마운트 실패 (화면 백화)<br/>• 신규 워크플로우 생성 버튼 미작동<br/>• 저장 시 지속적 에러 발생 | **1시간 이내** | 신규 작업 중단, 긴급 핫픽스 절차 가동 |
| **P2 (Medium)** | 특정 기능 오류, 우회 가능 | • 인스펙터 일부 속성 저장 지연<br/>• 컴포넌트 렌더링 경고 발생<br/>• 브라우저 콘솔 경고 누적 | **24시간 이내** | 정규 패치(V1.1) 계획에 편입하여 수정 |
| **P3 (Low)** | UI/UX 개선사항, 사소한 오타 | • 모바일 패널 접힘 안내 문구 보완<br/>• 미세 디자인 여백 정돈 | **정기 릴리스** | Backlog로 관리 및 다음 스프린트 반영 |

---

## 2. P0/P1 장애 발생 시 8단계 대응 프로세스

```text
[1단계] 장애 감지 (Incident Detected)
       ↓
[2단계] 신규 개발 및 변경 작업 전면 중단 (Stop Development)
       ↓
[3단계] 심각도 평가 (P0 / P1 판정)
       ↓
[4단계] 최신 정상 상태 식별 (Last Known Good Commit: 7ca6c9d)
       ↓
[5단계] 즉각적인 Vercel / DB 롤백 실행 (Rollback If Required)
       ↓
[6단계] 프로덕션 가용성 정상화 확인 (Verify Production Health)
       ↓
[7단계] 근본 원인 분석 (Root Cause Analysis - RCA)
       ↓
[8단계] 장애 보고서 작성 및 재발 방지책 확립 (Incident Report)
```
